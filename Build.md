# Project: Build the Official Website for NeauralStack Labs

## 1. Your Role

Act as a senior UI/UX designer, creative director, frontend engineer, accessibility specialist, conversion-rate optimization expert, and technical SEO engineer.

Your task is to design, implement, test, and document a complete, production-ready static website for **NeauralStack Labs**, a small technology services agency specializing in applied AI/ML engineering, intelligent automation, networking, and software development.

Do not merely generate a landing-page mockup. Build a cohesive, responsive, functional website with maintainable code and a clear path to deployment.

You have permission to inspect the project directory, create and modify files, run local tests, and fix issues. Before overwriting existing files, inspect the current project and preserve useful work.

## 2. Business Context

Brand name: NeauralStack Labs

Business type: Technology services agency / applied AI and engineering studio.

Team: Seven members, including the founder and partners. Some projects may be delivered collaboratively with freelancers where appropriate.

Target customers:
- Startups and early-stage companies
- Small and medium-sized businesses
- Founders building AI-powered products
- Businesses that need data analysis, ML prototypes, or model evaluation
- Teams that want to automate repetitive workflows
- Organizations needing authorized networking and IT support
- Clients who need Python scripts, APIs, integrations, and software development

Target market: International clients, including businesses that hire remote technical service providers.

Primary objective: Generate qualified inquiries and convert visitors into prospective clients.

Secondary objectives:
- Establish professional credibility.
- Explain technical services in language business owners understand.
- Demonstrate technical thinking through clearly labeled portfolio demonstrations.
- Make it easy for prospects to discuss a project.
- Provide a foundation for future case studies, blog posts, and service expansion.

Budget: Almost zero. Prefer free tools, static hosting, and no recurring infrastructure costs unless genuinely necessary.

## 3. Brand Positioning

Position NeauralStack Labs as a focused, technically rigorous, outcomes-oriented applied AI and engineering studio.

The brand should communicate:
- Technical competence
- Clear communication
- Honest delivery expectations
- Practical problem-solving
- Reproducible testing and measurable results
- Responsible AI and security-conscious engineering
- A small, focused team that works directly with clients

Avoid generic agency clichés, exaggerated claims, fake testimonials, fake client logos, fabricated revenue figures, invented credentials, and unsupported claims of guaranteed results.

Do not present portfolio concepts as completed client engagements. Clearly distinguish demonstrations, prototypes, experiments, and actual client work.

## 4. Services and Priority

Organize services in the following priority order.

### Service 1: Applied AI and Machine Learning
Examples:
- Dataset inspection, cleaning, and preprocessing
- Exploratory data analysis and visualization
- Feature engineering
- Classification and regression models
- Model training and hyperparameter tuning
- Cross-validation and group-based evaluation where appropriate
- Leakage detection and prevention
- Precision, recall, F1, ROC-AUC, and confusion-matrix analysis
- Model comparison and error analysis
- Prediction APIs and inference pipelines
- Model packaging and deployment assistance

Explain that model performance depends on data quality, the evaluation design, and the target environment. Never promise guaranteed accuracy.

### Service 2: Automation and AI Integration
Examples:
- Python workflow automation
- Scheduled reporting and data processing
- API integrations
- Document and spreadsheet processing
- Business workflow automation
- AI-assisted internal tools
- Repetitive task reduction
- Error handling, logging, and monitoring

Do not imply that every workflow requires an LLM or AI.

### Service 3: Networking and IT Engineering
Examples:
- Authorized network configuration and troubleshooting
- Network documentation and topology planning
- Connectivity diagnostics
- Linux and server administration assistance
- Basic monitoring and operational scripting
- Security-conscious configuration reviews

All network assessments must be explicitly authorized by the client. Do not market unauthorized access, intrusive scanning, or illegal activities.

### Service 4: Programming and Scripting
Examples:
- Python utilities and automation scripts
- REST API development and integrations
- Backend functionality
- Data-processing tools
- Bug fixing and code maintenance
- Technical prototypes
- Small internal developer tools

Only advertise capabilities that the team can realistically deliver. Make service descriptions editable so the business can narrow or expand its offerings later.

## 5. Visual Design Direction

Create a polished, distinctive technology brand rather than a generic template.

Design characteristics:
- Dark navy or near-black background
- Restrained electric blue and violet accents
- High-contrast typography
- Clean grid-based layouts
- Generous whitespace
- Subtle borders and layered surfaces
- Carefully controlled gradients
- Sophisticated technical illustrations
- Small, purposeful animations
- Consistent spacing, typography, and component styles

The visual direction should feel like a combination of a premium AI engineering studio and a modern software company.

Use visual elements that reinforce the work: data flows, connected nodes, model evaluation graphics, code-inspired patterns, and automation diagrams. Avoid excessive glowing effects, random floating objects, and visual clutter.

Do not copy another agency's website. Develop an original identity for NeauralStack Labs.

The website must also remain attractive in light of accessibility requirements. Use readable text, visible focus states, sufficient contrast, and reduced-motion support.

## 6. Required Website Sections

### A. Navigation
Include:
- NeauralStack Labs wordmark
- Services
- Approach
- Work
- About
- Contact
- A prominent “Discuss a Project” CTA

The navigation should be responsive, keyboard-accessible, and usable on mobile devices.

### B. Hero Section
Create a strong headline communicating that the agency turns data, AI, and engineering into practical solutions.

Suggested direction:

“Make your data work smarter.”

Supporting copy should explain that NeauralStack Labs builds practical ML solutions, automations, integrations, and technical tools for real business problems.

Include two CTAs:
- Discuss a Project
- Explore Our Services

Use an original visual showing an ML or data workflow, a connected technical system, or an elegant dashboard illustration.

Do not use fake dashboard statistics or imply that illustrative data represents real client results.

### C. Services
Create four visually consistent service cards, following the service priorities above.

Each card must include:
- Service title
- Plain-language summary
- Specific deliverables
- Appropriate visual or icon
- CTA to discuss that type of project

Make it obvious what a client can actually purchase.

### D. How We Work
Show a clear, credible process:

1. Discovery — understand the problem, constraints, data, and success criteria.
2. Scope — agree on deliverables, timeline, assumptions, and acceptance criteria.
3. Build — implement the solution with version control and documented decisions.
4. Validate — test against agreed requirements and relevant evaluation metrics.
5. Deliver — provide the agreed artifacts, documentation, and handover.

Do not promise fixed timelines before understanding a project.

### E. Selected Work / Technical Demonstrations
Include three portfolio demonstration cards:

1. ML Model Evaluation Lab
   - Dataset validation
   - Leakage checks
   - Baseline versus improved models
   - Precision, recall, F1, and confusion matrix
   - Reproducible evaluation reports

2. Automated Reporting Pipeline
   - Data ingestion
   - Validation and transformation
   - Scheduled report generation
   - Logging and error handling

3. Prediction API Prototype
   - Model inference endpoint
   - Input validation
   - Example requests and responses
   - Basic testing and deployment documentation

Until genuine projects are supplied, label these as “Concept,” “Prototype,” or “Technical Demonstration,” as appropriate.

Never invent clients, client testimonials, project outcomes, deployment histories, or business metrics.

Design each card so it can later link to a real GitHub repository, live demo, technical write-up, or case study.

### F. About
Introduce NeauralStack Labs as a seven-member team focused on practical technical delivery.

Emphasize a collaborative working model, clear communication, engineering discipline, and a willingness to define realistic project scopes.

Do not invent team member names, qualifications, employment history, or certifications.

Include editable placeholders for real team profiles if individual profiles are eventually desired.

### G. Why Work With Us
Explain differentiators using credible commitments:
- Scope and deliverables agreed in advance
- Transparent communication
- Testing and evaluation appropriate to the task
- Documentation and handover
- Solutions selected to fit the problem and budget
- Respect for client data and authorization boundaries

Avoid unsupported comparative claims such as “the best agency” or “100% success rate.”

### H. Frequently Asked Questions
Include useful questions such as:
- What types of projects do you accept?
- Can you work with an existing dataset or codebase?
- Do you work with international clients?
- How do you estimate project costs?
- Can you build a proof of concept before a larger engagement?
- How do you protect client data?
- What happens after project delivery?

Answers must be honest and editable. Do not invent policies the owner has not confirmed.

### I. Contact / Project Inquiry
Create a conversion-focused contact section.

Collect only useful initial details:
- Name
- Work email
- Company or project name (optional)
- Service category
- Project description
- Approximate budget (optional)
- Desired timeline (optional)

Include a clear privacy note explaining how submitted information will be handled once the owner confirms the actual process.

The form must not pretend to submit successfully if no backend or email integration exists.

Implement one of the following:
1. A configurable email-based contact flow that opens the visitor's email application with a prefilled message; or
2. A free, appropriate form service if the owner explicitly chooses one and its terms allow the intended use.

Prefer the simplest functional option. Document its limitations.

Provide a fallback contact email and an optional link to a professional business profile once supplied.

### J. Footer
Include:
- Brand name and short description
- Navigation links
- Services
- Contact details, once supplied
- Social links, only when real URLs are provided
- Copyright notice using the current year dynamically
- Privacy and legal links only when actual pages exist

## 7. Technical Requirements

First inspect the existing repository and identify its framework, package manager, entry point, and current functionality.

If the project is empty or no stack has been specified, use a lightweight static implementation with HTML, CSS, and JavaScript.

Do not introduce React, a build system, a database, or a backend without a clear benefit or an explicit requirement.

Requirements:
- Fully responsive design
- Mobile-first implementation
- Semantic HTML
- Reusable CSS variables and consistent design tokens
- Organized and maintainable code
- Functional navigation and CTA links
- Working mobile menu
- Functional form behavior that accurately reflects its implementation
- No dead buttons or placeholder links that appear operational
- No unnecessary paid APIs or services
- No exposed secrets or API keys
- No unnecessary collection of personal information
- No console errors
- No broken assets
- Graceful handling of missing configuration

Prefer locally implemented SVG illustrations and lightweight assets. If external fonts or other third-party assets are used, document the dependency and provide sensible fallbacks.

## 8. SEO and Sharing

Implement:
- Appropriate page title
- Meta description
- Canonical URL placeholder, clearly marked for configuration
- Open Graph title, description, and image configuration
- Social sharing metadata
- Favicon or a simple custom brand mark
- Correct heading hierarchy
- Descriptive links and image alternatives
- Search-engine-friendly content
- A basic robots.txt and sitemap only if appropriate for the final deployment setup

Do not invent a production domain. Use clearly documented placeholders until the owner provides one.

Do not add structured data containing unverified addresses, reviews, ratings, or company facts.

## 9. Accessibility and Performance

Aim for WCAG 2.2 AA-aligned accessibility practices.

Include:
- Keyboard navigation
- Visible focus indicators
- Accessible form labels and error messages
- Sufficient contrast
- Reduced-motion support
- Appropriate landmarks
- Logical heading structure
- Responsive text and spacing
- Lightweight assets
- Minimal JavaScript
- No unnecessary animation libraries

If browser testing tools are available, test mobile and desktop layouts and inspect accessibility issues.

## 10. Security and Privacy

- Never collect passwords or payment-card details on this static website.
- Never put API keys or private configuration in frontend code.
- Do not claim that a mailto form stores or securely transmits information on behalf of the agency.
- Do not add analytics, tracking, or cookies without an explicit decision.
- Clearly identify all external services and configuration requirements.
- Use authorized, client-approved methods for any networking-related work.
- Do not fabricate a privacy policy. If one is required before collecting inquiries, create an owner-review draft and clearly mark it as needing legal and operational verification.

## 11. Conversion Strategy

Optimize the website for qualified project inquiries, not vanity metrics.

Make the next step clear throughout the website.

Use direct language about deliverables, project fit, and the discovery process. Avoid manipulative countdowns, fabricated scarcity, fake client counts, fake reviews, and misleading claims.

Use the main CTA consistently: “Discuss a Project.”

Provide service-specific CTA links that can preselect the relevant service in the inquiry flow where practical.

## 12. Implementation Workflow

Follow this sequence:

1. Inspect the existing project and report the current structure.
2. Identify missing business information and configurable placeholders.
3. Establish the design system, typography, color palette, and component conventions.
4. Implement all required sections and interactions.
5. Check every link, form field, navigation item, and CTA.
6. Run any available linting, validation, build, and browser tests appropriate to the stack.
7. Fix discovered bugs and responsive-layout issues.
8. Review accessibility, SEO, performance, and security.
9. Write a README explaining how to run, configure, and deploy the site.
10. Produce a launch checklist and identify every owner action still required.

Do not stop after creating the hero section. Complete the entire agreed website before reporting completion.

## 13. Definition of Done

The project is complete only when:

- All required sections are implemented.
- The design is coherent and responsive across mobile, tablet, and desktop.
- All buttons and links work or are explicitly identified as awaiting real configuration.
- The contact flow works as documented.
- Portfolio concepts are not misrepresented as completed client work.
- No fake business information has been added.
- No critical console errors or broken assets remain.
- Accessibility and SEO basics have been checked.
- Setup and deployment instructions are included.
- All owner-supplied information still missing is listed explicitly.
- The final response summarizes implemented features, tests performed, files changed, known limitations, and next steps.

Begin by inspecting the existing project. Make reasonable design decisions independently, but never fabricate business facts or credentials. If critical business information is missing, use clearly marked configuration placeholders and continue implementation rather than blocking the entire project.
